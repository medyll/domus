# S5-01: Implement For<T> component for lists

**Story ID:** S5-01
**Status:** Pending
**Epic:** MVP 5 - Advanced Features
**Points:** 8

## Description

Implement the `For<T>` component that handles list rendering with efficient reconciliation using keys. This provides O(N) updates for lists instead of re-rendering the entire list. When items are added, removed, or reordered, only minimal DOM changes are made.

## Acceptance Criteria

- [ ] `For<T>` component struct with key function
- [ ] **Reconciliation algorithm** implements key-based diffing
- [ ] **DOM operations:** insertBefore, removeChild used correctly
- [ ] **Scope management:** Child scope created per item, disposed on removal
- [ ] **Performance:** 1000-item list updates in < 100ms
- [ ] **Memory:** No leaks when items removed/reordered
- [ ] **Tests pass:**
  - Add items to end
  - Remove items
  - Reorder items
  - Large lists (1000+)
  - Complex keys (not just strings)

## Implementation Notes

**Key Constraint:** Keys must be unique within the list (developer responsibility)

**Reconciliation Strategy:** Longest Common Subsequence (LCS) simplified
- Compare old keys with new keys
- Identify items to: add, remove, move
- Execute DOM operations in minimal set

**Decision Points:**
- **Key type:** `fn(&T) -> String` or generic `Fn` trait?
  - Recommendation: `Fn(&T) -> String` (simpler, flexible)
- **Rendering strategy:** Render all items upfront or lazy?
  - Recommendation: Render all (handle virtual scrolling later)
- **Move detection:** How to detect if item moved vs recreated?
  - Use key: if key exists in both old/new at different indices → move

## Detailed Reconciliation Algorithm

### Phase 1: Build Key Maps

```
OLD STATE: A B C
NEW STATE: B A C D

Create old_map:
  { "A": 0, "B": 1, "C": 2 }

Create new_keys_list:
  [ "B", "A", "C", "D" ]

Track which old indices map to new indices:
  {
    "B": old_idx=1 → new_idx=0,
    "A": old_idx=0 → new_idx=1,
    "C": old_idx=2 → new_idx=2,
    "D": old_idx=none → new_idx=3 (insert),
  }
```

### Phase 2: Identify Operations

```
For each new index, determine operation:

Index 0 (key "B"):
  - Old index: 1
  - Current DOM index: 1 (first of old)
  - Action: MOVE from index 1 to 0

Index 1 (key "A"):
  - Old index: 0
  - Current DOM index: 0 (now after move)
  - Action: MOVE from 0 to 1

Index 2 (key "C"):
  - Old index: 2
  - Current DOM index: 2 (after moves)
  - Action: KEEP (no move needed)

Index 3 (key "D"):
  - Old index: none
  - Action: INSERT new element

Result:
  - Remove: (none)
  - Move: B(1→0), A(0→1)
  - Insert: D at 3
  - Keep: C at 2
```

### Phase 3: Execute DOM Operations

```
EXECUTE_MOVES_AND_INSERTS:
  1. For each REMOVE: call removeChild
  2. For each MOVE: call insertBefore to reposition
  3. For each INSERT: create new element and call insertBefore
  4. For each KEEP: do nothing (already in correct position)

EXECUTION ORDER (important!):
  - Remove first (decreases indices)
  - Then move/insert (can use stable indices)
```

## Code Structure

```rust
// domius-web/src/list.rs

use crate::{create_effect, Signal, Scope};
use std::collections::HashMap;
use web_sys::{Element, Document};

/// Tracks a single item in the rendered list
struct ListItem<T> {
    key: String,
    value: T,
    scope_id: ScopeId,
    element: Element,
}

pub struct For<T: 'static> {
    items: Signal<Vec<T>>,
    key_fn: Box<dyn Fn(&T) -> String>,
    render_fn: Box<dyn Fn(&T) -> Element>,
    container: Element,
    current_items: Vec<ListItem<T>>,
}

impl<T: Clone> For<T> {
    /// Create a new For component
    pub fn new<K, R>(
        items: Signal<Vec<T>>,
        key_fn: K,
        render_fn: R,
        container: Element,
    ) -> Self
    where
        K: Fn(&T) -> String + 'static,
        R: Fn(&T) -> Element + 'static,
    {
        let mut for_comp = Self {
            items: items.clone(),
            key_fn: Box::new(key_fn),
            render_fn: Box::new(render_fn),
            container,
            current_items: Vec::new(),
        };

        // Initial render
        let initial_items = items.get();
        for_comp.render_initial(&initial_items);

        // Set up reactive update
        let items_clone = items.clone();
        let for_ptr = for_comp as *mut Self;
        create_effect(move || {
            let new_items = items_clone.get();
            // SAFETY: for_comp is owned by user, lives long enough
            unsafe {
                (*for_ptr).reconcile(&new_items);
            }
        });

        for_comp
    }

    /// Initial render: create all items
    fn render_initial(&mut self, items: &[T]) {
        for item in items {
            let key = (self.key_fn)(item);
            let element = (self.render_fn)(item);
            let scope_id = create_scope(Some(self.scope_id));

            self.container.append_child(&element).unwrap();
            self.current_items.push(ListItem {
                key,
                value: item.clone(),
                scope_id,
                element,
            });
        }
    }

    /// Reconcile old list with new list
    fn reconcile(&mut self, new_items: &[T]) {
        // Step 1: Build key maps
        let old_keys: Vec<String> = self.current_items.iter().map(|i| i.key.clone()).collect();
        let new_keys: Vec<String> = new_items.iter().map(|item| (self.key_fn)(item)).collect();

        // Step 2: Identify operations
        let ops = Self::diff_keys(&old_keys, &new_keys);

        // Step 3: Build new state
        let mut new_state = Vec::new();
        for (new_idx, new_item) in new_items.iter().enumerate() {
            let key = new_keys[new_idx].clone();

            match ops[new_idx] {
                DiffOp::Keep(old_idx) => {
                    // Reuse existing element
                    let old_item = &mut self.current_items[old_idx];
                    old_item.value = new_item.clone();
                    new_state.push(self.current_items[old_idx].clone());
                }
                DiffOp::Move(old_idx) => {
                    // Move element to new position
                    let old_item = &mut self.current_items[old_idx];
                    let el = old_item.element.clone();
                    self.container.append_child(&el).unwrap(); // moves to end
                    old_item.value = new_item.clone();
                    new_state.push(self.current_items[old_idx].clone());
                }
                DiffOp::Insert => {
                    // Create new element
                    let element = (self.render_fn)(new_item);
                    let scope_id = create_scope(Some(self.scope_id));
                    self.container.append_child(&element).unwrap();
                    new_state.push(ListItem {
                        key,
                        value: new_item.clone(),
                        scope_id,
                        element,
                    });
                }
            }
        }

        // Step 4: Remove items no longer in list
        for old_item in &self.current_items {
            if !new_keys.contains(&old_item.key) {
                self.container.remove_child(&old_item.element).unwrap();
                dispose_scope(old_item.scope_id);
            }
        }

        self.current_items = new_state;
    }

    /// Diff algorithm: compare old keys with new keys
    fn diff_keys(old_keys: &[String], new_keys: &[String]) -> Vec<DiffOp> {
        let mut old_map: HashMap<String, usize> = HashMap::new();
        for (idx, key) in old_keys.iter().enumerate() {
            old_map.insert(key.clone(), idx);
        }

        new_keys
            .iter()
            .map(|new_key| {
                if let Some(&old_idx) = old_map.get(new_key) {
                    // Key exists in both: Keep (may move)
                    DiffOp::Keep(old_idx)
                } else {
                    // Key is new: Insert
                    DiffOp::Insert
                }
            })
            .collect()
    }
}

#[derive(Debug, Clone, Copy)]
enum DiffOp {
    Keep(usize),  // Keep item at old index
    Move(usize),  // Move from old index
    Insert,       // Create new item
}
```

## Concrete Examples

### Example 1: Reordering

**Initial state:**
```
Items: ["Alice", "Bob", "Charlie"]
DOM:   <li>Alice</li> <li>Bob</li> <li>Charlie</li>
```

**Update to:**
```
Items: ["Bob", "Alice", "Charlie"]
```

**Reconciliation:**
```
old_keys: ["Alice", "Bob", "Charlie"]
new_keys: ["Bob", "Alice", "Charlie"]

Diff:
  new[0]="Bob" (was old[1]) → Move
  new[1]="Alice" (was old[0]) → Keep
  new[2]="Charlie" (was old[2]) → Keep

DOM after:
  <li>Bob</li> <li>Alice</li> <li>Charlie</li>
  (Only 1 DOM operation: move Bob)
```

### Example 2: Adding and Removing

**Initial state:**
```
Items: ["A", "B", "C"]
Keys: ["a", "b", "c"]
```

**Update to:**
```
Items: ["B", "C", "D"]
Keys: ["b", "c", "d"]
```

**Reconciliation:**
```
old_keys: ["a", "b", "c"]
new_keys: ["b", "c", "d"]

Diff:
  new[0]="b" (was old[1]) → Move to 0
  new[1]="c" (was old[2]) → Move to 1
  new[2]="d" (new) → Insert

Operations:
  1. Remove "a" element
  2. Move "b" to position 0
  3. Move "c" to position 1
  4. Insert new "d" element
```

### Example 3: Large List (1000+ items)

**Performance:**
- Adding 100 items to end: O(100) new DOM nodes
- Removing 50 items: O(50) removals
- Reordering entire list: O(N) moves in worst case

**Optimization:** Don't move nodes if already in correct order (keep is free)

## Common Pitfalls to Avoid

1. **Not using keys** — Without unique keys, DOM elements get reused incorrectly
2. **Mutating list in place** — Signal.set() with mutation doesn't trigger update
3. **Wrong operation order** — Removing before moving causes wrong indices
4. **Forgetting to dispose scopes** — Memory leak if removed items' scopes not disposed
5. **Index tracking** — Current DOM index changes during operations, don't rely on it
