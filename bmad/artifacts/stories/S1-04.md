# S1-04: Integrate auto-tracking between Signal and Effect

**Story ID:** S1-04
**Status:** Pending
**Epic:** MVP 1 - Reactive Core
**Points:** 3

## Description

Complete the auto-tracking system by having Signal.get() register the current Effect as a subscriber when called during Effect execution.

## Acceptance Criteria

- [ ] Signal::get() checks RUNNING_EFFECT via TLS
- [ ] If Effect is running, add it to subscribers (avoid duplicates)
- [ ] Subscriber lookup uses `Rc::ptr_eq` to prevent duplicates
- [ ] Signal::set() notifies all subscribers
- [ ] Each subscriber Effect is executed
- [ ] Unit tests verify:
  - Single effect tracks single signal
  - Single signal tracks multiple effects
  - Effect re-runs on Signal change
  - No duplicate subscriptions

## Implementation Notes

- Modify Signal::get() in `domus-core/src/signal.rs`
- Modify Signal::set() to execute effects (already sketched in S1-02)
- Effects execute synchronously (batching comes in S1-05)

## Code Structure

```rust
impl<T: Clone + 'static> Signal<T> {
    pub fn get(&self) -> T {
        RUNNING_EFFECT.with(|rt| {
            if let Some(effect) = rt.borrow().as_ref() {
                // Register effect as subscriber
                let mut subs = self.subscribers.borrow_mut();
                if !subs.iter().any(|s| Rc::ptr_eq(s, effect)) {
                    subs.push(Rc::clone(effect));
                }
            }
        });
        self.value.borrow().clone()
    }
}
```

## Testing Strategy

```rust
#[test]
fn test_auto_tracking() {
    let count = signal(0);
    let mut effects_run = 0;

    let count_clone = count.clone();
    let effect = create_effect(move || {
        assert_eq!(count_clone.get(), 0);
        effects_run += 1;
    });

    assert_eq!(effects_run, 1); // Initial run
    count.set(42);
    assert_eq!(effects_run, 2); // Re-run on change
}
```
