# S1-03: Implement TLS runtime and Effect type

**Story ID:** S1-03
**Status:** Done
**Epic:** MVP 1 - Reactive Core
**Points:** 5

## Description

Create the Thread Local Storage (TLS) runtime that tracks which Effect is currently executing, enabling automatic dependency tracking when Signals are read.

## Acceptance Criteria

- [ ] `thread_local! { static RUNNING_EFFECT: RefCell<Option<Rc<Effect>>> }`
- [ ] `Effect` struct with `execute: Box<dyn Fn()>`
- [ ] `Effect::new<F: Fn() + 'static>(f: F) -> Rc<Self>` constructor
- [ ] Effect execution flow:
  - Save current effect to TLS
  - Execute closure
  - Clear TLS
- [ ] Initial execution triggers dependency registration
- [ ] Auto-tracking integration with Signal (S1-04 completes)
- [ ] Unit tests for:
  - TLS manipulation
  - Effect execution
  - Multiple effects

## Implementation

Implemented TLS runtime and `Effect` in `domus-core/src/effect.rs` and scheduling in `domus-core/src/runtime.rs`.
Unit tests covering effect creation and TLS tracking pass locally (`cargo test -p domus-core`).

Notes:
- `RUNNING_EFFECT` TLS is present and used by `Signal::get()`.
- `Effect::new` accepts mutable closures (wrapped) to allow stateful test closures.
- Unsubscribe/disposal is left for S1-06.
