# S1-06: Implement Scope system for memory management

**Story ID:** S1-06
**Status:** Pending
**Epic:** MVP 1 - Reactive Core
**Points:** 5

## Description

Create the Scope system that tracks Effects and handles cleanup when components are removed. Each Scope has a unique ID and manages a list of Effects that should be disposed when the Scope is dropped.

## Acceptance Criteria

- [ ] `ScopeId` type (unique identifier)
- [ ] `Scope` struct with:
  - `id: ScopeId`
  - `effects: Vec<Rc<Effect>>`
  - `parent: Option<ScopeId>`
- [ ] Global scope registry: `HashMap<ScopeId, Scope>`
- [ ] `create_effect_in_scope(scope_id, f)` variant
- [ ] Scope drop unsubscribes all effects from signals
- [ ] Unit tests verify:
  - Effects unsubscribe on scope drop
  - No dangling references remain
  - Parent-child relationships maintained

## Implementation Notes

- Place in `domius-core/src/scope.rs`
- Use `AtomicUsize` counter for ScopeId generation
- Scope registry uses `thread_local!` + `RefCell<HashMap>`
- MutationObserver integration comes later (S2-xx)

## Testing Strategy

```rust
#[test]
fn test_scope_disposal() {
    let signal = signal(0);
    let scope = create_scope(None);

    let signal_clone = signal.clone();
    create_effect_in_scope(scope, move || {
        signal_clone.get();
    });

    // Scope still has subscribers
    let subscribers = signal.subscribers.borrow();
    assert_eq!(subscribers.len(), 1);

    // Dispose scope
    dispose_scope(scope);

    // Effect unsubscribed
    let subscribers = signal.subscribers.borrow();
    assert_eq!(subscribers.len(), 0);
}
```
