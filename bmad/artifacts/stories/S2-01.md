# S2-01: Create RSX parser for domus! macro

**Story ID:** S2-01
**Status:** Pending
**Epic:** MVP 2 - Rendering Engine
**Points:** 8

## Description

Implement the RSX (Rust Server eXtended) parser that transforms macro input into an AST. Support both Rust-style (`div(...)`) and HTML-style (`<div>`) syntax. The parser must detect which syntax is being used and transform it into a unified AST.

## Acceptance Criteria

- [ ] **Rust-style parsing:** `div(class: "x", id: "y") { children }` parses correctly
- [ ] **HTML-style parsing:** `<div class="x" id="y">children</div>` parses correctly
- [ ] **AST representation:** `RsxNode` enum with all variants correctly populated
- [ ] **Nested elements:** Multiple levels of nesting parse correctly
- [ ] **Attributes:** Both named (`class: "x"`) and HTML style (`class="x"`) work
- [ ] **Text nodes:** Static text `"hello"` and dynamic `{expr}` distinguished
- [ ] **Components:** Component references like `<Button />` or `Button()` recognized
- [ ] **Error messages:** Span-based errors point to correct location in source
- [ ] **Unit tests:** All test cases pass

## Implementation Notes

**Decision Point 1: Syntax Detection**
- Check first non-whitespace token: `<` → HTML style, else → Rust style
- Use `stream.peek()` from `proc_macro2::Span`

**Decision Point 2: HTML Parser**
- **Option A (Simpler):** Implement handwritten recursive descent parser
- **Option B (Robust):** Use `html5ever` or `scraper` crate
- **Recommendation:** Start with Option A (recursive descent), can switch later

**Key Implementation Steps:**
1. Create `Lexer` to tokenize input
2. Create `Parser` struct with `parse_node()` method
3. Implement `parse_element()`, `parse_text()`, `parse_dynamic()`
4. Build error handling with `proc_macro2::Span`

## Detailed Algorithm

### Rust-Style Parser (using `syn`)

```
PARSE_ELEMENT:
  1. Parse tag name (Ident)
  2. Check for `(` → parse attributes
     - Attribute: name: value pairs separated by `,`
     - Value: literal string, expr, or ident
  3. Check for `{` → parse children (recursive)
  4. Return Element node

PARSE_ATTRIBUTES:
  1. While not `)`:
     a. Parse key (Ident)
     b. Expect `:`
     c. Parse value:
        - Literal string → RsxAttr::String
        - `{expr}` → RsxAttr::Dynamic
        - Ident → RsxAttr::Ident
     d. Expect `,` or `)`

PARSE_CHILDREN:
  1. While not `}`:
     a. If starts with `"` → parse text
     b. If starts with `{` → parse dynamic expression
     c. If Ident or `<` → recursively parse element
     d. Collect all in Vec<RsxNode>
```

### HTML-Style Parser (handwritten)

```
PARSE_ELEMENT:
  1. Expect `<`
  2. Parse tag name (alphabetic until space/>/attribute)
  3. While not `>`:
     a. Skip whitespace
     b. If `>` → break
     c. If `/>`  → self-closing element
     d. Else parse attribute:
        - key=value format
        - Value can be quoted or unquoted
  4. If self-closing → return Element with no children
  5. Else parse children until `</tag>`

PARSE_CHILDREN (HTML):
  1. Create buffer for current text node
  2. While character != `<`:
     a. If `{` → flush text, parse dynamic expression
     b. Else append to buffer
  3. When `<` found:
     a. Flush text buffer
     b. Check if `</` (closing tag) or `<` (new element)
     c. Recursively parse element or break if closing
```

## Code Structure

```rust
// AST Definition
#[derive(Debug, Clone, PartialEq)]
enum RsxNode {
    Element {
        tag: String,
        attrs: Vec<(String, RsxAttr)>,
        children: Vec<RsxNode>,
    },
    Text(String),
    Dynamic(Expr),  // {some_signal}
    Component {
        name: String,
        props: Vec<(String, RsxAttr)>,
    },
}

#[derive(Debug, Clone, PartialEq)]
enum RsxAttr {
    String(String),     // class: "btn"
    Dynamic(Expr),      // on_click: {handler}
    Ident(String),      // some_value
}

// Main entry point
pub fn parse_rsx(input: TokenStream) -> Result<RsxNode, Error> {
    let tokens = input.into_iter().collect::<Vec<_>>();

    if tokens.is_empty() {
        return Err(error("empty macro input"));
    }

    // Detect syntax style
    match tokens[0].span().source_text().as_ref() {
        Some(s) if s.trim_start().starts_with('<') => {
            parse_html_style(&tokens)
        }
        _ => {
            parse_rust_style(&tokens)
        }
    }
}

// Rust-style parser using syn
fn parse_rust_style(tokens: &[TokenTree]) -> Result<RsxNode, Error> {
    let input = TokenStream::from_iter(tokens.iter().cloned());
    let parser = RustStyleParser::new(input);
    parser.parse_element()
}

// HTML-style parser (handwritten)
fn parse_html_style(tokens: &[TokenTree]) -> Result<RsxNode, Error> {
    let input = TokenStream::from_iter(tokens.iter().cloned());
    let source = input.to_string();
    let parser = HtmlStyleParser::new(&source);
    parser.parse_element()
}

// Helper: detect if next token is dynamic expression
fn is_dynamic(token: &TokenTree) -> bool {
    matches!(token, TokenTree::Group(g) if g.delimiter() == Delimiter::Brace)
}

// Helper: extract Expr from {expr}
fn extract_expr(group: &Group) -> Result<Expr, Error> {
    let stream = group.stream();
    syn::parse2::<Expr>(stream)
        .map_err(|e| error(&format!("Invalid expression: {}", e)))
}
```

## Concrete Examples

### Input & Output Examples

**Rust-style input:**
```rust
domus! {
    div(class: "container") {
        "Hello, "
        {name_signal}
        button(on_click: |_| count.set(1)) { "Click" }
    }
}
```

**Parsed AST:**
```
Element {
    tag: "div",
    attrs: [("class", String("container"))],
    children: [
        Text("Hello, "),
        Dynamic(Expr::Path(name_signal)),
        Element {
            tag: "button",
            attrs: [("on_click", Dynamic(...))],
            children: [Text("Click")]
        }
    ]
}
```

**HTML-style input:**
```rust
domus! {
    <div class="container">
        Hello, {name_signal}
        <button on_click={|_| count.set(1)}>Click</button>
    </div>
}
```

**Same AST output** (both styles produce identical tree)

## Testing Strategy

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_simple_element_rust() {
        let result = parse_rsx(quote! {
            div { "text" }
        });
        assert!(result.is_ok());
        let node = result.unwrap();
        assert!(matches!(node, RsxNode::Element { tag, .. } if tag == "div"));
    }

    #[test]
    fn test_attributes_rust() {
        let result = parse_rsx(quote! {
            div(class: "btn", id: "main") { }
        });
        assert!(result.is_ok());
        let RsxNode::Element { attrs, .. } = result.unwrap() else { panic!() };
        assert_eq!(attrs.len(), 2);
    }

    #[test]
    fn test_dynamic_text() {
        let result = parse_rsx(quote! {
            span { "Count: " {signal} }
        });
        assert!(result.is_ok());
        let RsxNode::Element { children, .. } = result.unwrap() else { panic!() };
        assert_eq!(children.len(), 2);
        assert!(matches!(children[1], RsxNode::Dynamic(_)));
    }

    #[test]
    fn test_nested_elements() {
        let result = parse_rsx(quote! {
            div { span { button { "text" } } }
        });
        assert!(result.is_ok());
        // Verify nesting depth
    }

    #[test]
    fn test_html_style() {
        let result = parse_rsx(quote! {
            <div class="btn">Click</div>
        });
        assert!(result.is_ok());
        // Should produce same AST as div(class: "btn") { "Click" }
    }

    #[test]
    fn test_event_handler() {
        let result = parse_rsx(quote! {
            button(on_click: |_| signal.set(true)) { "Go" }
        });
        assert!(result.is_ok());
    }
}
```

## Common Pitfalls to Avoid

1. **Forgetting brace groups** — `{expr}` inside text should be `Dynamic(expr)`, not `Text("{expr}")`
2. **Attribute value parsing** — `class: "btn"` vs `class={signal}` have different types
3. **Self-closing elements** — `<input />` should not expect closing tag
4. **Whitespace** — Preserve meaningful whitespace in text nodes, strip insignificant
5. **Error locations** — Use `span()` from tokens to point to exact error location
